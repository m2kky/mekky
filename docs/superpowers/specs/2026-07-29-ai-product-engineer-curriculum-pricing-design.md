# AI Product Engineer curriculum and pricing landing update

**Date:** 2026-07-29

## Objective

Update `/prompt-to-product` so the page sells a clear ten-week transformation instead of a long list of course topics. The page must show that learners finish with technical judgment, three real products, reusable project documents, and a route to launching and pricing their work.

The page should speak directly to beginners and non-technical builders in conversational Egyptian Arabic. It should not position the program as a coding course or a collection of AI tools.

## Primary message

خلال 10 أسابيع هتنتقل من شخص بيطلب من الـAI ويستنى النتيجة، لشخص يفهم المنتج والنظام، يكتب المطلوب، يختار التكنولوجيا، ويوجه فريقًا كاملًا حتى النشر.

The program is sold as a guided product-building journey, not as "32 lessons."

## Confirmed program model

- 10 weeks.
- 8 engineering units.
- 20 live sessions.
- Two sessions per week.
- Approximately 2.5 hours per session.
- Three applied products: an AI tool, a basic SaaS product, and an automation tool.
- Recordings, project files, structured feedback, and Demo Day.
- A documentation library of approximately 60 templates and examples. Learners are taught when to use each document rather than being asked to complete every template.

## Learner projects

Keep the three learner builds and connect each to its teaching purpose:

1. **AI Tool:** understand input, prompting, APIs, responses, state, and basic data handling.
2. **Basic SaaS:** apply the complete process from customer problem and documentation through UX, architecture, testing, and deployment.
3. **Automation Tool:** connect triggers, APIs, AI steps, actions, error handling, and monitoring.

The copy must say that these are not school examples. They are product types learners can demonstrate, extend, use internally, or sell.

Add a direct comparison section after the three learner projects.

| Typical Vibe Coding | AI Product Engineering |

## Eight-unit curriculum

Replace the current ten-stage data model with eight units. Preserve the existing alternating parallax/sticky-card motion and reduced-motion fallback.

Each unit card must show:

- Unit number and category.
- Unit title.
- Number of live sessions.
- Four lesson/topic labels.
- A concise explanation.
- The tangible unit output.
- The related project milestone where relevant.

### Unit 1: AI foundations and direction

- 2 sessions.
- AI models, assistants, copilots, and agents.
- Capabilities, limits, hallucinations, and verification.
- Prompt engineering.
- Context engineering and human review.
- Output: AI Working Manual and evaluation checklist.

### Unit 2: How the web works

- 2 sessions.
- Browser, server, HTTP, DNS, domains, and hosting.
- Frontend, backend, and full-stack systems.
- Website and web application types.
- CSR, SSR, SSG, and ISR.
- Output: Web Architecture Map.

### Unit 3: Data, APIs, and security

- 3 sessions.
- SQL, NoSQL, vector databases, and file storage.
- Data modeling and relationships.
- APIs, JSON, status codes, and webhooks.
- Authentication, authorization, roles, secrets, and environment variables.
- Output: ERD, API flow, and completed AI Tool.

### Unit 4: Product discovery and customer journey

- 2 sessions.
- Problem selection and niche.
- ICP and Jobs to Be Done.
- Value proposition and validation.
- Customer journey, user flow, MVP scope, and success measures.
- Output: validated problem, customer journey, user flow, and SaaS scope.

### Unit 5: Product documentation

- 3 sessions.
- Document selection and BRS.
- PRD, personas, user stories, and use cases.
- FRS, business rules, and data/API requirements.
- NFRS, acceptance criteria, risks, traceability, and change control.
- Output: project-specific documentation pack.

### Unit 6: UX and UI before code

- 2 sessions.
- Information architecture and navigation.
- User flows, wireframes, states, responsive design, and accessibility.
- UI exploration with Stitch.
- Figma prototype, design system, and developer/AI handoff.
- Output: sitemap, wireframes, prototype, design system, and UI handoff.

### Unit 7: Stack, architecture, and execution

- 3 sessions.
- Stack selection based on goal, cost, skills, maintenance, scalability, and lock-in.
- System design, components, data flow, ERD, API contracts, and failure points.
- Git, GitHub, repository structure, environments, and `AGENTS.md`.
- Task breakdown, AI team direction, code review, logs, and debugging.
- Output: stack decision, system design, repository, backlog, and first SaaS vertical slice.

### Unit 8: Production, pricing, and go-to-market

- 3 sessions.
- Testing, security, performance, logging, backup, and rollback.
- Vercel deployment, domains, production data, analytics, and monitoring.
- Automation design using triggers, APIs, AI, actions, retries, and alerts.
- Product cost, SaaS pricing models, packaging, offer, launch, and first customers.
- Output: deployed SaaS, working automation, pricing strategy, launch kit, and portfolio case study.

## Pricing strategy and research

The page must test the agreed course pricing strategy rather than ask a vague low-anchored budget question.

Pricing model:

- Founding Cohort target: 10,500 EGP.
- Founding payment plan: 3 payments of 3,500 EGP.
- Future standard price anchor: 14,900 EGP after case studies and learner outcomes.
- A future premium tier may be 19,900 EGP with limited individual project reviews. Do not advertise the premium tier during this waitlist test.

The public offer should mention that the official future price is 14,900 EGP and that accepted Founding Cohort members receive founding pricing. The exact founding price may remain undisclosed until enrollment opens.

Replace the existing budget ranges with a single pricing-validation question:

> لو تم قبولك في الدفعة التأسيسية، إيه نظام الاستثمار الأنسب ليك؟

Options:

1. `10,500 جنيه دفعة واحدة`
2. `3 دفعات × 3,500 جنيه`
3. `أحتاج خطة تقسيط أطول`
4. `السعر أعلى من ميزانيتي الحالية`
5. `السعر مناسب لو مستوى المتابعة زي الموضح`

This tests payment preference and price resistance without inviting the visitor to choose an arbitrary low range.
